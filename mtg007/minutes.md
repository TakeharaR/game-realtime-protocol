# ゲーム業界のリアルタイム通信プロトコルにおける課題を洗い出す

### 宿題 1 : 「疎通性」の呼び方について

- (第四回より)「到達性」もいまいち
    - 到達して終わりではないのでこれも違和感がある
        - 壊れてたり順番変わってたりいろいろある
    - 無理して一言で表そうとしない方が良さそう
        - 枕詞増やす、要素毎に定義する等……
- 「(仮)リアルタイム通信成立条件」というような大要素を作り、更に下位要素を入れる方向で決定
    - (仮) 疎通性/到達性
        - NAT/FW/キャリア制御等を越えて通信経路が成立するか
        - ミドルボックスにドロップされないプロトコルそのものの疎通性観点
            - 透過 Proxy 等の通過関連の観点も含める
        - コネクションのライフサイクルも関連がある
    - (仮) クオリティ(通信品質) 
        - 通信状況が理想的でない状況でも通信として扱えるか
        - パケロスやリオーダー、遅延等の品質観点
        - 輻輳制御のようなアルゴリズム
        - ゲームに必要な帯域を満たしているか、配信しながらも通信が可能か、というような観点もここに入れる
    - (仮) デュラビリティ(耐久性・永続性)
        - 通信環境が変化した場合の扱いが定義されているか
        - IP 変更や一時的な通信遮断等の環境変化観点
    - サービス対応 → 別軸に移動する
        - WAF や CDN 等のサービスに幅広く対応しているか
    - 備考
        - (仮) については次回までに運営が再度名称案を整理してくる
        - 宿題 2 の資料に上記内容でインクルード済み
